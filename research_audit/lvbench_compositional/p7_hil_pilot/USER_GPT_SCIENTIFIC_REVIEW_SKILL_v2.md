# Track B｜用户–GPT 科学审核 Skill v2（人工主导，Cursor 工程限定）

**生效依据：** 用户 2026-11-02 明确指令：“Seen Unseen，组合必要性验证什么的也我来吧，你来总结我的skill，别让cursor参与真正的数据构成了，它只能做工程方面的事情，我和你才有科学认证的能力。”

**定位：** 供用户与 GPT 在后续对话中复用的 *in-context 科学审核 Skill*；不是模型权重训练、不是自动裁决器。用户是最终科学裁决者；GPT 协助提出假设、分析反例、制定和核对研究协议、保存用户确认结论。Cursor 仅工程执行。未进行的新实验不得写成已验证。

## 1. 职责边界（USER_EXPLICIT_RULE；本次新增）

| 活动 | 用户 | GPT | Cursor |
|---|---|---|---|
| 事件事实、人物/动物身份、跨段关系 | 观察连续视频、最终判断 | 提炼已有用户观察、提出待确认推论或矛盾 | 抽帧/切片/媒体准备，绝不做科学语义裁决 |
| 组合 QA 与答案 | 审核、修改、确认 | 起草、指出错指代/证据位置、整理修订历史 | 仅呈现/保存用户与 GPT 已批准的数据文本 |

| Seen/Unseen 程序结构及训练/测试划分 | 最终批准 | 定义候选有向结构、检查同构、覆盖与泄漏 | 只按用户/GPT 已批准定义实现确定性检查 |

| 工程 | 下达需求 | 把科学需求转化为工程规格 | 视频抽取、浏览器本地端口访问、manifest/哈希、包生成、测试和 Git 操作 |

**Cursor 不能：** 自主选定正式研究目标签名或冻结 leave-out；自主挖掘/构造被当作科学事实的事件、QA、答案；将工程输出/启发式/用户 ACCEPT 自动升级组合必要性、Seen、Unseen 或 Gold；改变用户原判或以工程推测代替用户确认；没有明确指令就继续批量生产。之前 Cursor `STRUCTURE_LEAVEOUT_DEFINITION_V1.json` 是历史**提案/分析材料**，其“frozen”字段**不构成用户批准的有效正式划分**；不要删除历史记录，也不要将其自动作为后续基准。

**GPT 不能：** 自称看过仅存在于用户远程服务器的视频；把用户已看的有答案案例称为独立盲审；将自己提出的捷径风险当成用户的已确认判断。用户/GPT 对 DEV 的人工科学审核与未来独立盲测声明要分开。

## 2. 核心审核 Skill（已由用户明确要求）

1. **事实先于题目。** 对连续视频里真实发生的事件、动作极性、可见文字/数字、人物身份分别判断；稀疏静帧和自动标签只是线索，不能压过用户对连续视频的观察。
2. **事件 ≠ 身份绑定 ≠ QA 组合必要性。** `EVENT_VERIFICATION`、`CROSS_CLIP_IDENTITY_BINDING`、`QA_COMPOSITIONAL_NECESSITY` 三层独立。判定 A 和 B 是同一人物时，需要两段的身份线索；A 已有人名并不能取代看 B。身份通过绝不自动证明特定问题需要 A+B。
3. **问题、人物、答案必须相互对应。** GPT 出题时指出哪个片段提供人物指代、哪个片段提供答案。不要把同一片段的事件伪装成跨片段组合。用户修改问题和答案时保留原题、原答案、原 ACCEPT/REVISE，不覆盖；修订文本出现在旧 `answer` 字段时，不能擅自当作答案。
4. **真正的组合泛化不等于两段视频问答。** Seen/Unseen 必须比较完整*有向*算子依赖图（时间方向、实体绑定、动作/属性/顺序操作），区分已见原语、已见完整图、训练留出完整图；目标原语需要训练侧证据覆盖，视频/QA UID 不可跨 train/test 重叠。结构签名不能因为已有候选表现而事后挑选有利版本。
5. **必要性逐题审核。** 对最终固定题目，用户与 GPT 讨论 A-only、B-only、A+B：是否某单段已经包含足以答题的线索、是否需要跨段绑定、是否只在问显而易见的片段内部事实。结论可为“有条件支持/失败/待证”；没有实际隔离实验时不能写成已执行的盲测通过。
6. **只记看得到的事实。** 可见 `217` 不能无条件写成 `3217`；文字 `Fan Z.D.` 不自动扩展成单窗完整姓名；相邻剪辑、时间不重叠或镜头先后不能自动证明物理因果、参考来源或组合必要性。用户对解释性关系的接受原样保留，证据等级另议。
7. **不重复消耗人工。** 已确认的事实、身份和问答持久复用，只有具体尚未解决的科学疑点才请用户补判断。人工标注在本地时，用户发给 GPT → GPT 按原文入 GitHub → Cursor 只同步/存档；说明 GitHub 整理件并非本地文件字节副本。

**Skill 可操作表达：** “先提取用户实际看到的事实；再核对跨段指代和答案锚点；再由用户与 GPT 分析单段捷径和有向结构；最后由用户决定是否进入正式数据。无法证实的部分明确写待证。”

## 4. GPT 的主动建议（ASSISTANT_SUGGESTION；**并非用户已批准的科学事实**）

- 题目优先使用清楚的实体限定和明确的前后时段，尽量减少一段就能回答的捷径。
- 对混淆编辑/因果、人物/动物、姓名/号码、早期/晚期的候选先指出哪一步可能错，而不是强行产出答案。
- **人工必要性审计**可由用户判断 A-only/B-only/A+B 的证据依赖，GPT 辅助记录；这与独立盲审是不同证据等级。不因为 GPT 已知答案就禁止用户做自己的科学判断，也不把主观模拟当成真正隔离实验。
- 训练时真正未见的完整结构目标，需要用户明确选择；Sierra 等历史案例仅作为构图与错误分析的校准。Cursor 旧的 `P7_DIRECTED_STRUCTURE_LEAVEOUT_V1` 仅供比较，不自动生效。

## 5. 单轮最简操作（用户 + GPT）

1. **事实卡：** 用户看连续 A/B，记录实际事件、身份线索；GPT 只引用用户看到的或自己实际有权访问的证据。
2. **QA 卡：** GPT 提出清楚的 Q/A，用户接受、修改或拒绝；保留原版本和来源。
3. **科学裁决：** 用户与 GPT 逐题判断组合必要性、完整有向程序图、Seen/Unseen 归属和视频隔离；未完成写待证，用户确认后才改正式结果。
4. **工程落地：** GPT 给 Cursor 精确的**工程指令**，Cursor 仅输出媒体、索引、测试和经批准的标注文件，不创建新的科学结论。

**计数基线（截至 2026-11-02 本 Skill 建立时）：** Track A 历史已核验组合 QA 2 道/1 视频（校准）；P7 用户接受/确认候选 QA 7 道；R4 Seen 原语观察接受 4 项；正式合格新家族 0、Gold 0、正式 Seen/Unseen 0/0。这个数字是此前已存记录的状态，不是对本文件建立后进行任何新科学认证的宣称。
