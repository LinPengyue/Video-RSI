# 当前任务：以具体疑问驱动的训练轨迹诊断

你的交付是：从这批真实轨迹找出有证据、值得改、可复用的能力改进机会。
不是把每道错题当场解对，也不是让感知模型反复回答直到符合标准答案。
只完成诊断，保存报告后停下，等待编辑授权。保持同一会话，不另建Reviewer或压缩诊断模块。

## 先了解全局，再选择调查

阅读 training/index.json、当前 candidate/ 的实际实现和相关 SERVICES.md，理解工具、采样、
感知返回、记忆和决策如何接入。按索引查看全部案例的公开题目、选项、标准答案、原始标注和
实际轨迹；大文件按需读，不一次倾倒全部文本。已有 Gold Path 只是可质疑参考。
先在 analysis/notes.md 给各题留下简短初判：实际路线、关键观察/缺口、已知或待查。
这不是固定错误分类，也不要求每题进行工具调查。

优先调查：解释存在重要歧义、与多题共享机制、且有可执行验证方法的代表性错题。
已有轨迹足够时直接分析；答对题只查看已有轨迹以保护有效行为和寻找省帧机会，不专门重跑。
执行错误区分服务、工程和正常作答中的推理错误，不把一次服务失败当成能力不足。

## 一次调查的逻辑

每次调查前简短说明：尚不确定什么、此次取证能区分哪种解释、相对已有观察改变了什么。
用 INVESTIGATION.md 的真实观察/ASR/OCR/未修改Parent试跑获取结果；观察返回本会话并落盘。
观察后更新 notes.md：支持什么、反驳什么、仍然不清楚什么、是否值得继续。
这些是简短工作结论，不需要长篇思维记录或固定JSON诊断合同。

- 证据足够支持改进假设：记录结论，转向相关案例或综合分析。
- 原解释被反驳：改变解释，不重复追问以寻找支持。
- 有区分力的新办法：改变观察区域、采样、通道或具体问题再查。
- 同样观察没有新增信息，或没有可行验证办法：标为未解决，转向下一题。

例如左右冲突，应检查观察视角、目标识别或新镜头；不能只在同一批帧上重复问“左还是右”。
检查感知波动可以有目的地重复，但必须说明repeat_reason和此次复测要澄清什么；一致回答
也不自动证明真值。不要把有限预算耗在一个无法澄清的冲突上。

## 从案例到可复用能力

对错题可以用现有工具实际探索更好的取证路线。知道标注位置后直接观察，只能说明该处
信息可能可用；仍要问“不知道位置时，什么公开线索能使Solver找到它”。明确区分：
已实际尝试并取得证据、只走通一部分、需要修改/新增能力后才能验证。
原始Parent试跑不接收答案、标注、你的分析或辅助观察。你的工具串联是知晓训练标注的
辅助调查，不能冒充盲测Solver提升。工具不够时提出需求，不在诊断中修改任何Solver副本。

比较相关错题和正确题：哪些条件下存在同一机制？改变什么行为可能有用？哪些路径应保留？
允许提出Prompt、条件Skill/Workflow、工具、采样、视觉输出、记忆或推理方面的建议；不预设
修改模块，不强迫创造知识图谱或新工具，不按训练ID或数据集题型标签写专用答案规则。
单题可支持一个待验证假设，不足以证明普遍收益。没有证据时保留竞争解释，不指定唯一责任。

## 边界、预算和交付

不得修改candidate、Parent或临时Solver代码，不运行Gate。可以写调查请求、只读分析脚本、
notes.md和analysis.md。不要把标准答案放入Qwen请求让它证明；区间命中不等于看到关键证据，
Qwen答对不等于直接看到了答案，未覆盖标注也不排除ASR等有效证据。

共享API上限160次（DeepSeek/Qwen/试跑/重试合计），累计离线帧1024；单Solver预算保持不变。
都是上限，不要求用完。参考工具返回的实际剩余预算，留出整理报告的空间。
同参数请求默认返回已有观察，不是新的实测；连续忽略三次相同请求复用提醒会暂停，以免空转。
这不是每题调查次数限制；新验证办法仍可执行。报告与记录使用路径和版本名，不生成哈希。

notes.md是草稿和调查工作记录；analysis.md是最终综合报告。报告包括：批次范围与覆盖情况、
逐题简要结论、代表性错题的疑问/实际观察/尝试路线、共性机制、正确题省帧假设、建议修改方向、
适用条件、受保护路径及未解决问题。引用原始轨迹和取证记录，不以摘要替代原始证据。

全部案例已初步审阅且完成必要综合时，保存analysis.md后通过investigate.py提交finish_analysis。
未解决的题可以正常保留，不必全部调查成功；未审阅完或预算不足时提交partial并列出遗漏，
不能假装完成。提交后结束本轮，不自动编辑。仅有一个非空报告文件不代表已经正式提交。
